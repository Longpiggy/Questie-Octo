# Questie-Octo 1.0.91 — Full Audit

## Scope

This audit started from the clean 1.0.90 consolidation (runtime-equivalent to the accepted 1.0.85 behavior) and used the supplied current client/native UI/server/reference files. It covered the runtime package shape, compiled database, quest/map candidate reachability, Quest Log/Tracker state flow, asynchronous scheduler consumers, and the named Mulgore/Ragefire Chasm/Durotar player reports.

## Confirmed systemic defect

`Quest/QuestLog.lua` scans the native Vanilla Quest Log in scheduler batches. It snapshots `GetNumQuestLogEntries()` and then reads numeric native log indices over several frames. Native collapse/expand and quest add/remove operations can change those indices immediately.

Before 1.0.91, a new refresh request arriving during that scan only set `pending=true`. The old scan was still allowed to finish and publish first. That means one published `QuestLog.active` snapshot could contain early rows read from layout A and later rows read from layout B.

This is important because `QuestLog.active` is shared authority for the tracker, active-set/eligibility messages, objective/map rebuilding, completion state, event observation, and several availability guards. `TrackerDriver` also cleans saved tracking exceptions for quests missing from that published active set. A mixed snapshot can therefore manifest as several seemingly unrelated symptoms rather than one tracker-only bug.

The supplied pfQuest ClassicAPI reference contains explicit stale-`qlogid` protection after collapse/expand. Questie-Octo's timed-quest reader already performs the same class of quest-ID/index validation. The missing protection was the higher-level batched Quest Log transaction itself.

## 1.0.91 correction

The Quest Log scanner now has an unpublished scan generation. If any Quest Log refresh request arrives while a scan is running, the generation is invalidated immediately. On its next scheduler continuation, the obsolete scan discards all local replacement tables and queues a fresh pass. It does not publish `QuestLog.active`, snapshots, eligibility, map state, or change messages.

The correction is event-driven and bounded. It adds no polling, no recurring timer, no new `OnUpdate`, no distance work, and no database scan. Invalidation usually avoids wasted work because an already-obsolete scan stops instead of completing.

At the same time, tracker Open/Show-in-Quest-Log now validates its cached `logIndex` against the quest ID and re-resolves the current index before selecting it. Timed quests already used this safety pattern.

## Synthetic regression

A harness loads the real `Quest/QuestLog.lua` with a mocked Vanilla index-based Quest Log. It first publishes a stable six-quest snapshot, begins a normal four-row batched refresh, changes the native layout by collapsing an earlier header, then requests the refresh that such a structural change generates.

Against 1.0.90, the old continuation publishes a mixed/incomplete active set. Against 1.0.91, the same continuation records one invalidation/abort, leaves the prior six-quest authoritative state published, and the replacement scan recovers all six quests with the collapsed quests preserved as presentation-hidden.

## Named player reports

The following reported quests are present in the compiled Questie-Octo runtime and current audit inputs; no safe evidence supported deleting/replacing their normal quest records:

- `40446` — Halting Bristleback Expansion
- `40447` — Continuing Ceremonies
- `5722` — Searching for the Lost Satchel
- `5723` — Testing an Enemy's Strength
- `834` — Winds in the Desert (5 Sacks of Supplies)

Their presence/reachability is consistent with the systemic active-snapshot failure being a better common explanation than several unrelated missing database records. Live testing is still required before claiming those specific reports solved.

`40587` — A Dryad's Gratitude is confirmed by the supplied server data as a 300-second timed quest. Questie-Octo's compiled data retains its timed flag. No speculative objective/map override was added.

`772` — Rite of Vision remains a distinct scripted/zero-native-objective edge case. Its server template supplies Water of the Seers as a source item but no ordinary item/creature/gameobject objective. Questie-Octo's IR-aware zero-objective completion guard can therefore be conservative for this quest. The audit found many IR-only quests with differing semantics, so no global IR rule was changed.

## Database and package audit

The pruned runtime validator passes with:

- 6,701 quests
- 3,635 item records
- 14,138 unit records
- 1,639 object records
- 124 reference-loot records
- 189 item-requirement records
- 108 candidate maps / 8,675 quest-map links

Recompiling `Data/runtime/` from the packaged development inputs reproduced the shipped runtime files byte-for-byte before version packaging.

The independent starter/candidate reachability check reports only the known intentional `CLUCK!` representative-source exception: Chicken (620) exists on many maps, while Questie-Octo intentionally advertises quest 3861 through one representative Westfall location instead of every Chicken spawn. No general candidate-index loss was found.

## Other full-audit findings intentionally left unchanged

- Existing asynchronous builders for Items/Objectives/AvailableQuests/Prepared/Map/Nodes/ZoneBootstrap already use generation or revision guards appropriate to their incremental work. The mutable native Quest Log scan was the notable missing transactional guard.
- Scheduler limits remain unchanged: O(1) FIFO, maximum two jobs per frame, approximately 4 ms budget when measurable.
- No proximity engine, new polling, map-identity rewrite, objective-source merge, or tracker scroll-anchor logic was added.
- `Hide Completed Objectives` keeps the accepted 1.0.83 behavior.
- 1.0.87, 1.0.88, and 1.0.89 runtime experiments remain rejected and absent.

## Validation completed

- All 126 Lua files load syntactically through the available system Lua 5.4 parser. This is a static syntax check, not an exact Vanilla Lua 5.0 runtime claim.
- Synthetic old/new Quest Log transaction regression passes on 1.0.91 and reproduces the old mixed-snapshot publication on 1.0.90.
- Runtime database validator passes.
- Runtime recompilation is identical to the packaged runtime data.
- Final package/TOC checks are performed during packaging.
